# 刮削控制（PotatoVN 插件）

按类别控制 PotatoVN 刮削哪些内容，并关掉最耗时的制作人抓取。

## 它解决什么问题

PotatoVN 刮削时会顺带抓取**制作人员**（原画、编剧、音乐等），而这一项：

- **没有任何开关可以关闭** —— 混合搜刮器的启用设置里只有 11 个信息类型，不包括制作人
- **开销极大** —— 每一位制作人要单独发一次 API 请求并下载一张头像
- **无法取消** —— 刮削任务一旦开始只能等它跑完

实际影响可以参考一组真实数据：80 个游戏累计 3133 位制作人员，全部抓完需要约 **6000 次网络请求**，全部夹杂在日常刮削过程中。

本插件把制作人从刮削流程里摘出来，做成可开关、可单独补抓的任务。

## 六个分类开关

| 开关 | 说明 | 开销 |
|---|---|---|
| 游戏信息 | 游戏名、简介、会社、发售日期、标签、评分等 | 小 |
| 封面图 | 列表显示的小图 | 中 |
| 标题图 | 详情页顶部横幅 | 中 |
| 角色信息 | 角色列表，每人要查一次并下载两张图 | 大 |
| 游玩状态 | 同步 Bangumi / VNDB 上的评论评分 | 小 |
| **制作人员** | 原画、编剧、音乐等 | **极大** |

四个预设：**极速**（只要文字）、**标准**（信息+封面，推荐）、**丰富**（+标题图+角色）、**全部**（含制作人）。

## 宿主已经有什么，本插件补什么

PotatoVN 本身在批量刮削时会弹出一个「选择要刮削的信息」对话框，提供 5 个选项（游戏信息 / 标题图 / 封面图 / 角色 / 游玩状态）。本插件的差异在于：

1. **补上制作人开关** —— 宿主的对话框里没有这一项，而它恰恰是最慢的
2. **记住选择** —— 宿主的对话框每次都要重新勾选，本插件的配置持久化
3. **覆盖入库刮削** —— 扫描入库时宿主固定用「全部」，不走那个对话框，必然触发制作人；本插件摘掉监听后，任何入口都不再触发

## 安装

插件是 WinUI3 类库，**必须在 Windows 上编译**，没有现成的二进制包。

好消息是：**不需要安装 Visual Studio**。
PotatoVN 官方自己的 CI 也是用命令行工具 + 云主机构建的，本插件沿用同样的方式。

三种编译方式任选，推荐第一种。

### 方式一：GitHub Actions 云编译（推荐，零安装）

不用装 Visual Studio。GitHub 提供免费的 Windows 云主机，预装了全套编译环境。

1. 在 GitHub 新建一个空仓库（不要勾 README）
2. 把本文件夹的内容全部上传
3. 打开仓库的 **Actions** 标签页 → 左侧选 **Build Plugin** → 点 **Run workflow**
4. 等 3~5 分钟，在 **Artifacts** 区域下载 `plugin-pvnplugin`

工作流会自动拉取 PotatoVN 宿主源码，无需手动配置。

> 首次进入 Actions 页时 GitHub 会要求启用，点确认即可。

### 方式二：命令行编译（不装 VS 图形界面）

只装命令行工具，比完整 VS2022 小得多：

1. 装 **.NET 8 SDK**：https://dotnet.microsoft.com/download
2. 装 **Visual Studio 2022 生成工具**：
   https://visualstudio.microsoft.com/zh-hans/downloads/#build-tools-for-visual-studio-2022
   安装时勾选 **「WinUI 应用程序开发」** 工作负载
3. 在本文件夹打开 PowerShell，运行：

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\build.ps1
   ```

脚本会自动下载宿主源码、编译、打包，并告诉你产物在哪。

### 方式三：Visual Studio 2022

1. 装 VS2022（勾选「WinUI 应用程序开发」工作负载）
2. 下载宿主源码到 `PotatoVN` 目录：

   ```bash
   git clone --depth 1 https://github.com/GoldenPotato137/PotatoVN.git PotatoVN
   ```

3. 打开 `PotatoVN.ScrapeControl.sln` → 切 **Release** → 生成解决方案
4. 产物在 `PotatoVN.App.Plugin.ScrapeControl\artifacts\plugin.pvnplugin.zip`

### 本次修复记录

- **v1（首版）**：误用了 `GameParseType` 作为编译期类型。该枚举定义在宿主主程序（GalgameManager）里，而插件只能引用 `GalgameManager.WinApp.Base`，编译期拿不到 → 9 个 CS0246 报错。
  改为**运行时按名字查枚举 + 整数位掩码**，完全不依赖编译期类型。
- **v2**：改签名后漏改 3 处调用（`IsEmpty(ScrapeProfile.Build(_data))`），导致 CS1503。已全部改为 `IsEmpty(_data)`。

### 安装插件包

拿到 `plugin.pvnplugin.zip` 后：

1. PotatoVN → 设置 → 其他设置 → 打开 **开发者模式**
2. 设置 → 插件 → 右上角「添加插件」按钮 → 选择该 zip
3. 启用插件，并切到别的页面再切回来刷新

> 需要 PotatoVN **v1.10.1 或更高版本**。

## 使用方法

装好后在三处出现：

- **设置 → 插件 → 刮削控制**：调整六个开关、套用预设、执行批量刮削
- **侧边栏「按配置刮削」**：按当前配置刮削全部游戏
- **游戏详情页右侧面板**：只对当前游戏刮削，或单独补抓该游戏的制作人员

**推荐流程**：先用「极速」把元数据快速补齐 → 需要图片时切「标准」或「丰富」→ 制作人单独补抓。

## 实现说明

给想改代码或好奇的人：

**制作人开关是怎么实现的。** 宿主在 `StaffService` 构造时挂了一个事件监听：

```csharp
galgameService.GalgameMutated += OnGalgameMutated;
```

只要刮削结果含 `GameInfo` 就会触发，且没有任何开关能关掉。本插件通过反射找到这个事件，从调用列表里摘掉属于制作人服务的那个 handler；开启时再挂回去。`Services/HostBridge.cs` 里有完整实现。

**为什么不用硬编码字段名。** 反射是按「方法签名」和「类型名」查找目标的，不是死记字段名，宿主小改不易失效。所有反射只做一次并缓存。

**卸载时会还原。** 插件卸载时会自动把监听挂回去，避免宿主在卸载后一直处于「没人抓制作人」的状态。

**刮削为什么要在 UI 线程发起。** 刮削内部会改动绑定到界面的对象，必须走 UI 线程。插件 API 只提供了同步的 `InvokeOnMainThread`，所以采用「UI 线程启动、后台 await」的方式，既不会跨线程改 UI，也不会卡住界面。

## 已知限制

- **依赖反射**，宿主若大幅重构刮削服务，插件可能失效。失效时会优雅降级：界面仍可打开，但会明确提示「未能接管」，不会假装生效
- 只能对**全部游戏**批量刮削——宿主没有把「当前选中的游戏」开放给插件，单游戏操作请到游戏详情页
- 停止制作人抓取后，制作人只在手动补抓时更新
- 与宿主自带刮削走的是同一个底层方法，因此同样受信息源限流影响；被限流时可把「游戏之间间隔」调大
